# Superseded StatusLamp Plan

**SUPERSEDED — historical context only. Do not implement from this document.**

An earlier concept proposed multiple named status lamps managed by a generalized status service. It also considered configurable colors, JSON persistence, an event bus for status changes, and packaging the lamp as a reusable control library.

Those ideas exceeded the demonstrated need and are not current product or architecture decisions. Consult the current documents under `docs/` and the active plan under `docs/plans/` instead.
